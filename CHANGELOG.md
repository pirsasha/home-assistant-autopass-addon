# История изменений

## 0.19.74

- кнопка «Авто» в экспозиции теперь действительно включает
  `exposure_auto_enabled` и снимает ручной override.

## 0.19.73

- переключения экспозиции пишутся в `data/px_exposure/events.jsonl` для
  доказательства ровно двух записей в сутки.

## 0.19.72

- добавлено автоматическое переключение экспозиции PX-камер по восходу/закату:
  день `electronicShutte=0` (1/3), ночь `=5` (1/100);
- меняется только `exposure.electronicShutte`; `flickerCtrlModel`, WDR, HLC,
  детекция и распознавание не изменяются;
- проверка каждые 10 минут, запись только при отличии;
- ручной режим не перезаписывается планировщиком;
- API экспозиции, backup и откат; координаты и запас настраиваются на камеру.

## 0.19.71

- добавлена отключаемая настройка «Авто-повтор открытия для стоящей машины»
  в редакторе PX-камеры;
- интервал повтора по умолчанию 15 секунд, максимум 3 повтора;
- повтор только после разрешённого номера, при свежей машине в зоне и без
  пересечения линии;
- без прочитанной зоны команда не отправляется.

## 0.19.70

- добавлена ручная кнопка «Обновить сессию» для PX-камеры;
- ошибка `101` больше не показывается как «зона выключена»;
- при ошибке используются последние успешно прочитанные зоны с пометкой STALE;
- автоматического re-login на каждый запрос нет.

## 0.19.69

- добавлен read-only shadow-слой «стоящая машина»: packet-5 vehicle + зона
  region-entrance + непустой номер + dwell 5/15 секунд;
- линия (`line_crossing`) подавляет повторное открытие;
- отображается только `would_open`/`would_retry`; команды воротам и реле не
  добавлены;
- endpoint `/api/px-cameras/shadow`; блок «Shadow: стоящая машина» в настройках.

## 0.19.68

- исправлен POST диагностики PX: добавлен `Content-Type: application/json`;
- добавлен визуальный read-only блок «Параметры камеры»: фокус, выдержка,
  WDR/HLC, резкость и zoom через существующую сессию воркера;
- версия 0.19.67 не перезаписывается.

## 0.19.67

- добавлен read-only endpoint `/api/px-cameras/ivs-geometry`: зоны
  region-entrance и линии line-crossing читаются через существующую сессию
  PX-воркера, без нового логина и записи в камеру;
- добавлен read-only endpoint `/api/px-cameras/camera-settings`: focus mode,
  exposure/shutter, image/WDR и zoom читаются через существующую сессию;
- в настройках появилась визуальная схема зон/линий (SVG, не видео);
- правки камеры и автоматическое управление воротами не добавлены.

## 0.19.66

- P2.1a: packet-5 vehicle geometry diagnostics now separate current and
  historical state: fresh/stale tracks, fresh/total stationary candidates,
  fresh/total ambiguous observations and stale-transition counters;
- candidate freshness uses monotonic receiver time; a moving, ambiguous or stale
  candidate is never shown as a confidently stationary current vehicle;
- UI labels are Russian and explicitly distinguish "сейчас" from "всего";
- no vehicle authorization, gate control or Shadow Mode was added.

## 0.19.65

- добавлена выключенная по умолчанию metadata-only диагностика PX WebSocket:
  счётчики типов пакетов, безопасные категории событий, наличие rule/zone/object/
  bbox/timestamp полей, повторы object ID и интервалы обновлений без номеров,
  изображений, сырого JSON и сырых идентификаторов;
- P1.1: поддержаны вложенные packet-2 `events[].objects[]` без двойного счёта
  одинаковых top-level/nested объектов; повторы object ID разделены на
  within-event, same-packet, across-packet и cross-event; identity stability
  явно помечена как UNVERIFIED, а неизвестная структура packet 10 не выдаётся
  за отсутствие объектов.

## 0.19.64

- исправлен вход через Home Assistant Ingress после усиления проверки
  ingress-заголовков в 0.19.58: Uvicorn больше не подменяет сетевой peer на
  `X-Forwarded-For`, поэтому HA-пользователь снова определяется автоматически,
  без локального пароля;
- добавлен регрессионный тест на конфигурацию `run.sh`.

## 0.19.63

- предупреждение при выдаче длинного пропуска: если срок больше 90 дней, перед
  сохранением появляется диалог «Пропуск будет действовать N дней — до …; обычно
  пропуска выдают на срок визита, длинный придётся закрывать вручную». Для
  годовых кнопка другая («Всё равно выдать») и выделена красным;
- то же предупреждение при одобрении заявки на длинный срок — годовой пропуск
  больше не появится «случайно» ни через форму пропуска, ни через заявку
  арендатора;
- добавлены тесты контракта интерфейса на предупреждение.

## 0.19.62

- подсказка при одобрении заявки: если по номеру уже действует пропуск,
  покрывающий период заявки, в диалоге видно «уже действует пропуск до …: заявка
  привяжется к нему и доступ не изменится». В массовом подтверждении пишется,
  сколько выбранных заявок уже покрыты. Так диспетчер видит «пустые» одобрения
  заранее — именно они и создавали пары «длинная + короткая» заявка;
- отчёт «Длинные пропуска с заявками» (в «Импорте и экспорте»): находит пропуска
  длиннее 90 дней, к которым привязаны короткие заявки, показывает их списком и
  позволяет заблокировать все одной кнопкой. Блокировка закрывает проезд, история
  проездов и карточки сохраняются;
- в списке заявок появились поля «покрывающий пропуск» (`covered_pass_id`,
  `covered_pass_until`) — по ним работают и подсказка, и массовое подтверждение;
- добавлены тесты: подсказка о покрытии, отчёт (длинный пропуск с заявками,
  короткий пропуск, длинный с одной заявкой, права) и контракт интерфейса.

## 0.19.61

- исправлен фильтр «Арендатор» в «Пропусках»: он искал только организацию в
  заявке, а в колонке показывается имя заявителя, если организация пуста —
  поэтому по видимому значению (например, `snsexpress`) фильтр ничего не находил.
  Теперь поиск идёт по той же логике, что и показ, а подсказки поля заполняются
  реальными значениями из списка;
- добавлена массовая блокировка и разблокировка пропусков: выделить строки →
  «Заблокировать выбранные (N)» / «Разблокировать выбранные (N)». Блокировка
  закрывает проезд, но сохраняет историю проездов и карточки — в отличие от
  удаления. Действует право `manage_passes`, всё пишется в аудит
  (`pass_bulk_status_changed`);
- выделять строки теперь можно и без права удаления (раньше чекбоксы были только
  у тех, кто может удалять);
- добавлены тесты: поиск по имени заявителя и по организации, блокировка и
  разблокировка, повторная блокировка, ненайденные id, права, аудит.

## 0.19.60

- удаление подтверждается своим диалогом вместо браузерного `confirm()`: после
  галки «больше не показывать» Chrome переставал показывать диалоги и молча
  возвращал «отмена» — из-за этого удаление «перестаёт работать». В диалоге есть
  своя галка «больше не спрашивать до перезагрузки страницы» (на сессию, без
  влияния на браузер), Esc и «Отмена» работают предсказуемо;
- в «Пропусках» появилось массовое удаление: выделение строк, «выбрать все» и
  кнопка «Удалить выбранные (N)» — одно подтверждение и одна операция на сервере
  вместо десятков запросов по одному элементу. Удаляется так же, как по одному:
  вместе с автомобилем; владелец остаётся, если у него есть другие машины;
- одиночное удаление, чёрный список, тарифы парковки, камеры, заявки и
  восстановление базы тоже переведены на общий диалог;
- интерфейс после обновления подхватывается сразу: версия статики в странице
  совпадает с версией add-on, а сама страница отдаётся без кэша
  (`Cache-Control: no-store`). Раньше браузер мог продолжать работать со старым
  `app.js`/`app.css` — версия в ссылке застыла на 0.19.54, из-за чего изменения
  «не появлялись». За совпадением версий теперь следит тест;
- добавлены тесты: массовое удаление пропусков (включая владельца с несколькими
  машинами, ненайденные id, права и аудит) и контракт интерфейса (нет браузерных
  подтверждений, есть выделение строк и вызов массового удаления).

## 0.19.59

- PX-события больше не получают ссылку на снимок во Frigate: такого события там
  нет, и в журнале была заведомо битая картинка
  (`…/api/events/px-…/snapshot.jpg`). Теперь запись остаётся без ссылки, а кадр
  дописывает поток, когда он придёт. Уже записанные события с такой ссылкой тоже
  исправляются: кадр из потока заменяет битую ссылку на реальный файл;
- добавлены тесты: у PX-события нет ссылки на Frigate, у события Frigate ссылка
  прежняя, битая внешняя ссылка заменяется настоящим кадром.

## 0.19.58

- закрыта уязвимость входа: заголовки `X-Remote-User-*`, которыми Home Assistant
  передаёт пользователя панели, больше не принимаются с чужого адреса. Раньше
  публичный адрес объекта позволял представиться кем угодно и читать журнал
  (номер, ФИО, телефон), а на объекте без пользователей — получить роль
  администратора. Доверенные сети задаются опцией add-on
  `ingress_trusted_networks` (по умолчанию `172.30.32.0/23`, `127.0.0.1/32`,
  `::1/128`); запрос с недоверенного адреса идёт обычным путём — локальный вход
  или отказ, а в журнал пишется предупреждение с адресом источника;
- пользователей, созданных автоматически по входу HA, теперь можно удалять: и в
  интерфейсе, и командой поддержки `delete_user` (с защитой последнего
  администратора). Раньше такие записи оставались в списке навсегда;
- добавлены тесты: доверенные сети, отказ в подмене личности, удаление
  ingress-пользователя, защита последнего администратора.

## 0.19.57

- фото PX-событий: кадр из потока событий теперь догоняет уже записанную поездку.
  Камеры этой серии отдают HTTP-API, только пока поток событий закрыт (проверено
  на объекте: `/picture/snapshot` без логина тоже обрывается, а статическая
  страница при этом отвечает). Значит, снимок «сейчас» невозможен в принципе, а
  кадр события (packet_type 2) часто приходит позже пакета с номером. Теперь он
  дописывается в событие, которое осталось без фото;
- в счётчиках PX-камер появились `frames_late` (сколько фото догнало события) и
  `last_frame_error` (почему кадр не получен) — причина видна в интерфейсе, без
  сбора логов;
- добавлены тесты: привязка кадра к событию, сохранение уже имеющегося фото,
  игнорирование событий Frigate и старых записей, ошибка привязки не мешает
  обработке номеров.

## 0.19.56

- в «Журнале проездов» появился фильтр по времени: «Время с» и «Время по».
  С выбранной датой это точный интервал этого дня, без даты — тот же интервал в
  любой день (например, «с 19:00 по 20:00» покажет проезды за все дни). Граница
  «по 19:21» включает всю минуту, поэтому проезд в 19:21:37 не теряется; можно
  указать и секунды. Ночное окно («с 22:00 по 02:00») тоже работает;
- время фильтруется и в счётчиках журнала, и в живом автообновлении списка;
- добавлены тесты: интервал в любой день, минутная и секундная границы, ночное
  окно, счётчики, отказ на некорректное время и регрессия фильтра по датам.

## 0.19.55

- в «Журнале проездов» дата и время показываются с секундами — так проезды
  удобно сверять по камерам между собой (в карточке события и в подписи снимка
  тоже);
- добавлен регрессионный тест: журнал форматирует время с секундами.

## 0.19.54

- кадры PX-событий: облачный снимок больше не открывает вторую сессию камеры —
  он берётся через уже подключённую сессию воркера, а при сетевом сбое клиент
  сначала повторяет запрос тем же cookie и логинится только если сессия правда
  умерла. У камер этой серии одна активная сессия, и лишний вход обрывал поток
  событий: номера приходили, а фото — нет. В счётчиках камеры появился `logins`,
  чтобы это было видно в интерфейсе;
- даты пропусков проверяются при записи: форма (Excel-дата, `2026-09-16`,
  `16.09.2026`, `16/09/2026`, ISO с часовым поясом), разумный год (2000–2100) и
  порядок («до» позже «с»). Опечатка вида `20226-09-16` больше не попадает в
  базу: при импорте строка получает понятную причину, при вводе и правке — 422;
- исправлены фильтры списков: смена статуса или дат в «Заявках» и в «Журнале
  проездов» перезагружает список, а не добавляет строки к прежним. Из-за этого
  фильтр «Подтверждены» показывал и ожидающие заявки, а счётчик — прошлую выборку;
- импорт пропусков показывает причины отказа по строкам (как и импорт заявок);
- в «Импорте и экспорте» появилась карточка «Проверка дат»: находит пропуска и
  заявки с испорченной датой (не разбирается или год вне 2000–2100), чтобы дату
  можно было исправить в карточке;
- в шаблоне выгрузки Excel у колонок «Действует с» и «Действует до» появилась
  подсказка о формате. Колонки, их порядок и правила импорта не менялись;
- идентификатор события камеры PX больше не повторяется: к метке времени добавлен
  счётчик процесса, иначе два проезда подряд в одну миллисекунду склеивались в
  одно событие (этот id — первичный ключ таблицы состояний);
- добавлены регрессионные тесты на форматы дат, отказ, импорт, фильтры списков и
  сессии PX-камер (лишний логин в камеру).

## 0.19.53

- «Список для КПП» больше не падает с ошибкой 500 из-за одной испорченной записи:
  пропуск с неразбираемой датой (например, год из пяти цифр — `20226-09-16T00:00`)
  ронял и счётчик, и скачивание. Теперь такая запись не попадает в список на КПП
  и получает причину «Некорректный срок действия — исправьте пропуск»;
- решение о проезде по испорченному сроку — отказ (fail-closed): пропуск с
  неразбираемой датой не открывает ворота, а не «разрешает без ограничений»;
- пауза между открытиями ворот не падает, если у события испорчена метка времени;
- импорт заявок показывает причины отказа по строкам: вместо «Ошибок: 11»
  оператор видит, например, «Строка 2: Период заявки превышает лимит: максимум
  16 дн.». Частые причины — лимиты «Заявка вперёд, дней» и «Максимальная
  длительность заявки, дней»;
- добавлены регрессионные тесты на пропуск с испорченной датой.

## 0.19.52

- исправлена работа «Списка для КПП» в разделе «Импорт и экспорт»;
- ошибки и статус скачивания теперь отображаются прямо на карточке;
- исправлена загрузка счётчика и колонок после входа через Home Assistant Ingress;
- устранено перекрытие интерфейса закрытым окном проверки старых заявок;
- исправлена обработка нескольких автомобилей, следующих подряд через открытый шлагбаум;
- новые автомобили больше не теряются из-за паузы между командами открытия;
- пауза теперь ограничивает только повторную физическую команду шлагбауму;
- автомобили без доступа и номера из чёрного списка всё равно фиксируются в журнале;
- исправлена обработка парковочных въездов/выездов при проезде колонной;

## 0.19.51

- улучшена проверка старых заявок: система корректно учитывает роль пользователя
  на момент создания заявки по истории аудита;
- пользователи, которым позже меняли роль, больше не попадают в ручную проверку
  только из-за отличия текущих прав;
- неоднозначные или удалённые старые пользователи по-прежнему безопасно
  отправляются в «Ручную проверку»;
- окно проверки старых заявок стало компактнее: основные данные помещаются
  без горизонтальной прокрутки;
- добавлены группировка повторяющихся проблемных пользователей, подробности по
  строке и более понятные причины ручной проверки;
- улучшено отображение на планшетах и небольших экранах.

## 0.19.50

- добавлено разовое безопасное обслуживание legacy-заявок: предварительный
  просмотр (DRY RUN) и применение пересчёта сроков, созданных до введения
  текущих ограничений заявителя (14 дней вперёд, 16 дней длительность);
- ограничения применяются только к заявкам обычных заявителей: у создателей с
  правом подтверждения заявок (администратор, диспетчер) длинные заявки
  сохраняются, их сроки не сокращаются;
- если права создателя нельзя доказать (профиль неизвестен, нет снимка прав в
  аудите, неоднозначная смена роли) — заявка помечается «Ручная проверка» и
  автоматически не меняется;
- связанные временные пропуска пересчитываются безопасно: для обычных заявок
